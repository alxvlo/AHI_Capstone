## /explain Workflow

### Step 1: Identify What to Explain
- What is the subject? (concept / code / error / decision)
- What is the user's current knowledge level?

### Step 2: Plain English First
- Explain in 2-3 sentences as if speaking to a student
- Use an analogy if helpful

### Step 3: Technical Detail
- Add technical depth for those who want it
- Show a minimal code example if applicable

### Step 4: Real-World Context
- Where is this used in production?
- Why does it matter?

### Step 5: Check Understanding
- Ask: "Does this make sense? Want me to go deeper on any part?"
