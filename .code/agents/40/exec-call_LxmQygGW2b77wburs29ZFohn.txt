--- README.md ---
   1: # AHI Capstone Repository
   2: 
   3: Internal collaboration repository for the American Hospital Inc. PEME monitoring and result access system.
   4: 
   5: This repo is optimized for team execution, planning, QA, and traceable delivery rather than public distribution. It contains the application code, Supabase migrations, test assets, and the project memory bank used to keep Jira, GitHub, and implementation aligned.
   6: 
   7: ## Project Summary
   8: 
   9: - **Project:** Real-Time PEME Monitoring and Result Access System for American Hospital Inc.
  10: - **Primary goal:** Replace fragmented paper-heavy PEME tracking with role-based dashboards, secure portals, and real-time workflow visibility.
  11: - **Current phase:** Iteration 2, Sprint 07 - lifecycle foundation and E2E readiness.
  12: - **Team:** Keith Avellaneda, Deejay Clark Datu, Alexander Velo.
  13: 
  14: ## What Is In This Repository
  15: 
  16: - `app/` - Next.js App Router pages and route entrypoints.
  17: - `components/` - reusable UI and dashboard presentation components.
  18: - `features/` - feature-level business logic that should not live directly inside route files.
  19: - `lib/` - shared utilities, Supabase access helpers, validation, and routing logic.
  20: - `supabase/` - schema migrations, seed data, and hosted-project database changes.
  21: - `scripts/` - local and seeded-environment audit/verification scripts.
  22: - `tests/` - Vitest unit and integration coverage.
  23: - `memory-bank/` - planning, architecture, workflow, and project-state documentation.
  24: - `shared/`, `.agent/`, `.opencode/` - collaboration and local AI/tooling support files; not part of the deployed app runtime.
  25: 
  26: ## Canonical Docs
  27: 
  28: Start here when you need project context before changing code:
  29: 
  30: 1. `memory-bank/pid.md` - project scope, constraints, objectives, and success metrics.
  31: 2. `memory-bank/design-doc.md` - architecture and system design decisions.

  37: ## Tech Stack
  38: 
  39: - **Frontend:** Next.js 15, React 19, Tailwind CSS 4.
  40: - **Backend/BaaS:** Supabase Auth, PostgreSQL, Realtime, RLS.

 136: ## Team Workflow
 137: 
 138: This repo follows a Jira + GitHub collaboration model.
 139: 
 140: - **Jira** is the source of truth for planning, assignments, sprint state, and acceptance criteria.
 141: - **GitHub** is the source of truth for code, review, and merge history.
 142: - Every branch, commit, and PR should reference the Jira key.
 143: 
 144: Examples:
 145: 
 146: - Branch: `SCRUM-31-e2e-case-lifecycle`
 147: - Commit: `SCRUM-31: Wire lifecycle bootstrap path`
 148: - PR title: `[SCRUM-31] Wire lifecycle bootstrap path`
 149: 
 150: See `memory-bank/guides/workflow-policy.md` for the full policy.
 151: 
 152: ## Working Agreements
 153: 
 154: - Keep feature logic in `features/` or `lib/`, not buried inside route files.
 155: - Treat `memory-bank/` as the planning and context layer, not as disposable notes.
 156: - Do not commit generated artifacts such as `coverage/`, `node_modules/`, local caches, or `.env.local`.
 157: - Run `npm run qa:local` before opening a PR when your change affects app behavior.
 158: - If a change impacts workflow, security, or compliance, update the relevant memory-bank document as part of the same effort.
 159: 
 160: ## Repository Hygiene

 163: 
 164: - `.agent/` and `.opencode/` store local agent/tooling configuration and shared references.

  40:   if (message.length <= limit) {

  47: function buildRedirectPath(
  48:   returnPath: string,
  49:   options: {
  50:     notice?: string;
  51:     error?: string;
  52:   }
  53: ) {
  54:   const normalized = normalizeReturnPath(returnPath);
  55:   const url = new URL(normalized, "http://localhost");
  56:   url.searchParams.delete("notice");
  57:   url.searchParams.delete("error");
  58: 
  59:   if (options.notice) {
  60:     url.searchParams.set("notice", truncateMessage(options.notice));
  61:   }
  62: 
  63:   if (options.error) {
  64:     url.searchParams.set("error", truncateMessage(options.error));
  65:   }
  66:

  68:

 143: async function getStatusId(
 144:   supabase: CurrentUserRoleContext["supabase"],
 145:   domain: "CASE" | "VISIT",
 146:   code: string

 148:   const { data: statusRow, error: statusError } = await supabase
 149:     .from("status_code")

 151:     .eq("domain", domain)
 152:     .eq("code", code)
 153:     .eq("isactive", true)
 154:     .maybeSingle();

 156:   if (statusError) {
 157:     return null;
 158:   }

 161:     return null;
 162:   }

 167: function generateCaseNumber(attempt = 0) {
 168:   const now = new Date();
 169:   const datePart = now.toISOString().slice(0, 10).replace(/-/g, "");
 170:   const timePart = now.toISOString().slice(11, 19).replace(/:/g, "");
 171:   const randomPart = Math.floor(Math.random() * 900 + 100);
 172:   const attemptPart = attempt > 0 ? `-${attempt}` : "";
 173: 
 174:   return `AHI-${datePart}-${timePart}-${randomPart}${attemptPart}`.slice(0, 30);
 175: }
